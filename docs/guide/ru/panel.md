# Панель Lab

[English](../panel.md) · Русский

**Цель:** открыть на своей машине страницу только для чтения, показывающую работу
сервиса Lab — проекты, шаги и циклы сценариев, факты, все эксперименты и ход
работающей кампании — и затем закрыть её. **Готово, когда** страница по ссылке
из `lab panel` показывает исправный сервис, вы открыли экраны из [шага 4](#шаг-4-откройте-экраны),
а `lab panel stop` сообщает об остановке панели.

Панель только *читает*. Все действия (запуск оценки или кампании, приёмка
изменения) остаются командами `lab …` или в вашем инструменте. Панель содержит
оболочку, обзорные экраны и экраны экспериментов (кампания, измерение, оценка,
приостановленная кампания, diff), предоставляемые небольшим локальным шлюзом.

Страница состоит из двух частей. **[Шаги](#шаги)** — список действий.
**[Справочные сведения](#справочные-сведения)** ниже объясняют содержимое
панели, модель безопасности и действия при недоступном сервисе. Точные wire-формы —
в [справочнике API панели](../../../lab/docs/api/panel.md).

## Перед началом

- Lab установлен ([Установка](install.md)) с необязательными зависимостями панели (шаг 1).
- Вы знаете свой Lab home (`--home`, `LAB_HOME` или умолчание). Панель находит
  сервис через `<home>/service.sock`, как любая команда `lab`; везде передавайте один `--home`.

### Шаг 1. Установите extra панели

**Сделайте:** установите Lab с extra `panel` (он добавляет `fastapi` и
`uvicorn`; extras `service` и `dev` уже включают их).

```bash
pip install 'evolution-lab[panel]'
```

При работе с собранным wheel установите его так же с extra:
`pip install './evolution_lab-<version>-py3-none-any.whl[panel]'`.

**Готово, когда:** `python -c "import fastapi, uvicorn"` проходит в том же
окружении, что `lab` (`lab panel --help` работает и без extra, поэтому не
помогает проверить). Без extra `lab panel` на переднем плане завершается с
`panel_dependencies_missing`; с `--background` завершается отсоединённый
потомок, команда сообщает `panel_start_failed`, подробности — в
`<home>/logs/panel.log`. Это относится к любой ошибке запуска отсоединённого
потомка (нет extra, порт занят и т. д.): с `--background` родитель сообщает
`panel_start_failed`, а `panel_start_timeout` (потомок не успел стать готов и
остановлен) содержит его `pid`.

### Шаг 2. Запустите сервис

**Сделайте:** в одном терминале запустите сервис для своего home
([CLI и локальный сервис](cli.md#запуск-и-остановка-сервиса)).

```bash
lab serve --home ~/lab-home --state ~/lab-state/dev81-b22 \
  --execution-wheel /path/to/evolution_lab-….whl --execution-wheel /path/to/evo_skills-….whl
```

**Готово, когда:** `lab serve` вывел строку готовности, а `<home>/service.sock`
существует. (Панель запускается и без сервиса, но показывает
`service_unavailable` до его запуска — см. [ниже](#когда-сервис-недоступен).)

### Шаг 3. Запустите панель и откройте ссылку

**Сделайте:** во втором терминале запустите панель. На переднем плане:

```bash
lab panel --home ~/lab-home --open
```

Или отсоединённо, чтобы терминал остался свободен:

```bash
lab panel --home ~/lab-home --background --open
```

`--open` открывает выведенную ссылку в браузере по умолчанию; без него
скопируйте ссылку сами. `--port N` выбирает фиксированный порт (по умолчанию —
любой свободный).

Вывод — одна строка `panel: http://p<random>.localhost:<port>/?token=<token>`
(с `--json` — объект `lab-panel-runtime/1`). Имя хоста новое при каждом
запуске (см. [Безопасность](#безопасность)); браузеры разрешают любое имя
`*.localhost` в эту машину, а сама панель слушает только `127.0.0.1`.

**Готово, когда:** браузер показывает страницу панели с состоянием сервиса `ok`
и списком проектов (пустым, если ничего не подключено). Запустите кампанию в
сервисе, и её строка будет обновляться в реальном времени.

### Шаг 4. Откройте экраны

**Сделайте:** пройдите экраны из боковой панели (каждый — адрес `#/…` той же
страницы; [таблица ниже](#что-показывает-панель) объясняет содержимое).

1. **Projects** (`#/projects`, домашняя страница): прочитайте *Now* над таблицей, затем нажмите *All projects* и прочитайте строки проектов.
2. **Project** (`#/projects/<id>`): нажмите имя проекта.
3. **Facts & confirmations** (`#/projects/<id>/facts`): воспользуйтесь ссылкой внизу экрана проекта.
4. **Experiments** (`#/experiments`): нажмите *All experiments* сбоку, затем строку.
5. **State reference** (`#/states`): нажмите *State reference* сбоку.
6. Нажмите *Light theme* (или *Dark theme*) внизу боковой панели.
7. **Эксперимент** — откройте одну кампанию (см. [экраны эксперимента](#шаг-4a-откройте-эксперимент) ниже).

**Готово, когда:** каждый экран показывает данные или ясно объясняет их
отсутствие (загрузка, явная строка пустого home или `No experiments yet`,
`Unavailable (<code>)`); при приостановленной кампании экран проекта показывает
вердикт продолжения и, когда Lab его разрешает, точную копируемую строку
`lab resume …`; переключение темы сразу меняет страницу и сохраняется после перезагрузки.

### Шаг 4a. Откройте эксперимент

**Сделайте:** на *Experiments* нажмите строку кампании.

1. **Campaign** (`#/operations/<id>`): начните с карточки состояния: *Now*,
   *Progress* (или *Where it stopped*) и *Result*. Ниже — история пауз,
   раунды и попытки, родословная Чемпионов, независимая приёмка, образцы,
   сумма токенов Target Service и скачивание отчёта. Настройки, маршрутизация, проверки
   и проба Reflector свёрнуты ниже. Работающая кампания показывает *In progress*
   и обновляется сама.
2. Нажмите id попытки в строке: **Measurement**
   (`#/operations/<id>/measurements/<measurement>`) — панели *Decision* и
   *Confidence* попытки, изменения относительно baseline раунда, гипотезы
   Reflector в прочитанном Lab виде, коды ошибок Editor и результаты по кейсам.
3. Нажмите *Open full diff* (или *diff against original* в родословной): **Diff**
   (`#/operations/<id>/diff`) — выберите пару версий, прочитайте файлы с числом
   `+`/`−` и фрагментами изменений.
4. Вместо этого нажмите строку оценки: **Evaluation** показывает те же карточки
   и кейсы для одного измерения.
5. Для приостановленной кампании **Suspended** показывает общую карточку
   состояния, вердикт продолжения и последние данные о паузе, затем раунды,
   родословную и запуски. Когда Lab разрешает продолжение, доступна копируемая
   строка `lab resume …` (и `lab agent stop …`, если нужен новый target).
   Выполните её в терминале; панель ничего не запускает.

**Готово, когда:** каждый экран показывает данные или словами объясняет их
отсутствие (см. [три формулировки](#что-показывает-панель) ниже); у каждой
команды есть кнопка *Copy*; diff кампании с удалёнными результатами показывает
`results_deleted` вместо файлов.

### Шаг 5. Проверьте панель

**Сделайте:** спросите, работает ли панель для этого home.

```bash
lab panel status --home ~/lab-home
```

**Готово, когда:** выводится `panel: running <link> (pid …, since …)`.
`panel: not running` означает, что home не занят панелью.

### Шаг 6. Остановите панель

**Сделайте:** остановите её (панель переднего плана также останавливается по Ctrl-C).

```bash
lab panel stop --home ~/lab-home
```

**Готово, когда:** выводится `panel: stopped (pid …)`, а последующий
`lab panel status` печатает `panel: not running`. Ссылка больше не работает.

## Справочные сведения

### Что представляет собой панель

- **Только чтение.** Принимаются только `GET` (и `HEAD`); всё остальное
  отвечает `405 method_not_allowed`. Действия выполняются через `lab …`.
- **Нет собственных данных.** Панель не читает Lab home и не интерпретирует
  JSON сервиса: она пересылает разрешённый список маршрутов `GET` сервиса через
  его Unix-сокет ([API: что пересылается](../../../lab/docs/api/panel.md#what-is-forwarded))
  и предоставляет статическую страницу.
- **Одна панель на Lab home**, обеспечивается блокировкой `<home>/panel.lock`.
  Вторая `lab panel` для того же home завершается с `panel_already_running` и,
  если может, называет ссылку работающей панели.
- **Ссылка живёт один запуск.** При каждом запуске создаются новый токен и имя
  хоста; ссылка прежнего запуска не работает. Откройте ссылку один раз: панель
  отвечает перенаправлением на `/` и сессионной cookie (`lab_panel_<port>`,
  чтобы панели разных home на одной машине не перезаписывали cookie друг друга).

### Что показывает панель

По одной строке на экран. Всё поступает из пересылаемых панелью маршрутов `GET`
сервиса; панель добавляет арифметику над ответом Lab (счётчики, длительность,
связь операции с проектом), но не собственные суждения и никогда не читает
сырые файлы Core. Экран или раздел с отсутствующими данными говорит об этом
словами вместо пустого места. Есть три формулировки:

- `Core does not record this` — используемая версия Core не записывает данные
  (связь попытки с гипотезой Reflector; число токенов subprocess Editor).
- `Not read by Lab yet — next version` — данные есть в файлах Core, но эта версия Lab ещё их не читает.
- `Unavailable (<code>)` — чтение не удалось. Код — собственная ошибка Lab
  (`not_found`, `service_unavailable`, …), либо `http_<status>`, если в ответе
  кода нет, `invalid_json`, `network_error`, `invalid_id` для id, который
  панель отказывается запрашивать, или `diff_unparsed` для неразбираемого diff.

Где они встречаются:

- `Core does not record this` — на *Measurement*: какая гипотеза Reflector
  использована попыткой и число токенов Editor.
- `Not read by Lab yet — next version` — вход и рассуждения Reflector и Editor,
  подробности кейса (вход, эталон, диалог, вердикт судьи), описание изменённого
  файла и разбивка baseline по владельцам (*Suspended campaign*).
- Гипотезы Reflector показываются как записаны. По ADR-0019 пункт 4 их текст
  может цитировать части эталонных ответов; обращайтесь со скриншотом этого
  блока как с исходными данными.

`Unavailable (<code>)` обозначает ошибку чтения — отдельно для элементов,
где панель объединяет несколько чтений: экспериментов проекта сбоку, ячеек
*Connect*/*Evolve*/*Champion* строки Projects, проекта строки Experiments,
карточки продолжения приостановленного цикла (поэтому `none yet` и `—` всегда
означают, что Lab ответил и ничего не нашёл; элемент последнего ответа помечается
*stale*). Там, где Lab помечает весь раздел `unavailable` или `not_started`
(прогресс, время, результаты), показывается *Unavailable* или *Not started*.
Когда Lab также даёт код причины (время запуска эксперимента: `unreadable`,
`core_raw_unsupported`), список Experiments добавляет его: *Unavailable · Unreadable*.

| Экран | Что показывает | Чего не показывает |
|---|---|---|
| Боковая панель и баннер | Сбоку: состояние сервиса, все проекты с экспериментами (точка состояния, короткий id), переключатель темы. На странице: баннер, когда сервис или панель перестают отвечать. | — |
| **Projects** (главная) | Постоянный блок *Now* для работающего эксперимента или подтверждённого простоя; далее строки проектов с шагами *connect*, циклами *evolve* и версией Чемпиона; строка сервиса. | Среднюю оценку Чемпиона (только версию). |
| **Project** | Запуски проекта, новые сначала: сверху текущий цикл (как его отмечает Owner Core), иначе последний прогон, как конвейер; ниже история — другие циклы и выполненные разовые сценарии вроде `connect`, по строке, раскрываемой по требованию. Возможные, но ещё не выполненные шаги (следующий цикл, невыполненный или недоступный сценарий) не показаны. Каждый шаг с состоянием, временем, причиной устаревания или блокировки; для приостановленного цикла — вердикт продолжения и разрешённая Lab копируемая строка, как в `lab resume`. | Однострочное описание каждого шага (Lab возвращает только заголовок). |
| **Facts & confirmations** | Факты проекта (действует ли каждый, откуда известен, почему устарел) и записанные подтверждения. | — |
| **Experiments** | Все кампании и оценки home с фильтром по виду: проект, статус, прогресс, результат (исход и версия Чемпиона), состояние результатов, время начала, длительность. Строка открывает экран эксперимента. | Фильтр *Needs attention* (суждение); среднее в столбце *Result*. |
| **Campaign** | Карточка состояния, история пауз, раунды и попытки, родословная, независимая приёмка, образцы, токены target (*partial: target calls only*), скачивание отчёта; настройки, маршрутизация и диагностика свёрнуты. | Заштрихованные или *infrastructure* ячейки; использованную гипотезу; токены Editor; confidence (на экране Measurement). |
| **Measurement** | Одно измерение: для попытки панели *Decision* (gate, финальное решение, переход Чемпиона) и *Confidence* с историей look; карточки (метрики, покрытие, повторы, ошибки вызовов, токены), сравнение с baseline раунда, сводка diff попытки, гипотезы Reflector раунда как записаны, ошибка Editor, карточки событий ролей и подробности выбранного кейса над таблицей. | Описание изменённых файлов; рассуждения, удалённые Core; незаписанное содержимое ролей. |
| **Evaluation** | Те же карточки и подробности кейса для единственного измерения оценки; полоса образцов — первая строка *Cases* (ячейка выбирает кейс), с числом critical-pass. | Незаписанное содержимое кейса. |
| **Suspended campaign** | Общая карточка состояния, вердикт и копируемая строка продолжения, *Latest pause evidence*, раунды, родословная, запуски, полоса baseline и скачивание отчёта; настройки и маршрутизация свёрнуты. | Разбивку baseline по владельцам и заштрихованные ячейки. |
| **Diff** | Пары версий (оригинал–Чемпион, Чемпион–Чемпион, попытка–baseline раунда); файлы из patch и изменения бинарных файлов и режимов со своими маркерами; `+`/`−` считаются из текста patch. | — |
| **State reference** | Все известные панели коды состояний с подписями и цветом, четыре вердикта продолжения и вид только что начатой кампании (ещё без событий Core). | — |

На экранах кампании (и приостановленной тоже) и оценки доступна **Download report (.md)**,
пока результаты операции присутствуют: панель читает `report.md` и сохраняет
через браузер как `report-<operation id>.md`; при ошибке показывает код рядом с
кнопкой и ничего не сохраняет. Место и права файла определяет браузер.

Три честных исхода разделены: *Not better* нейтрален, *Not enough data* —
янтарный, *Infrastructure* — фиолетовый. Значение любой метки ищите в **State reference**.

Панель dev79 читает представление `lab-campaign-view/15` и отклоняет любую другую
версию (`Unavailable (unsupported_schema)`) на каждом экране, который его
читает, — campaign, suspended campaign, measurement и diff — до чтения полей;
ничего из него не показывается, перечисленные измерения не запрашиваются. Такой
же Unavailable применяется при неверном типе читаемого скаляра: числовые
confidence margins family 14 остаются числами, статистические величины family
15 должны сохранять `{value, exact}`; допускающие null id эталонов — строки или
null. Это защита читаемых панелью полей, а не второй полный декодер закрытой формы.
Опубликованная пара dev72 сохраняет представление кампании `/14`; её запуски остаются со своими producing wheels.

Карточка состояния кампании и приостановленной кампании показывает три взгляда
на одни записанные факты. *Now* содержит состояние, предложение из полей Lab
и исходные коды; неизвестные исходы и причины остаются кодами. Пауза и
диагностика последнего запуска могут присутствовать одновременно, не утверждая,
что запуск выполнялся. *Progress* или *Where it stopped* показывает число
раундов и попыток; покрытие доступно только активной кампании. *Result* считает
записанных Чемпионов, ссылается на родословную и перечисляет ограничения и
уведомления Lab, не выбирая Чемпиона. Первые два пункта видимы сразу, остальные
раскрываются. Если представление нечитаемо, исход неизвестен, а не отсутствует;
состояния чтения и метки устаревания указывают доступные ответы.

Домашний *Now* различает работающий сервис, простой, загрузку и недоступность
по health сервиса. Последний известный ответ отмечается *stale*. Последняя
закрытая операция показывается только если все нужные сводки проектов свежие
и подходящая операция найдена. Метка *Failed* у рефлексии называет класс ошибки
(например, `oracle_leak`).

Кампания с манифестом `/15` в режиме `observe` несёт нейтральное ограничение
*Observe gate not enforced*: прохождение gate делает попытку финалистом без
статистической проверки; приёмка требует финального контраста Core. Метки
*Accepted* и *Promoted* сохраняют цвет; ограничение перечислено в *Limits on this result*
карточки состояния, ограничениях отмеченных представлением раундов и попыток, как
небольшая нейтральная отметка в карточках родословной продвинутых Чемпионов и
на странице измерения Чемпиона. Если ограничения кампании `/15` прочитать не
удалось (`gate_mode: null`), gate неизвестен: в тех же местах и у каждого
раунда и попытки указано *Gate unknown — not evidence of quality*. У кампании
`statistical` такого ограничения нет: gate применяется, его режим нейтрально
отмечен в Confidence попытки, решение Core показано у каждой попытки.

Свёрнутый блок **Campaign setup & routing** одной строкой суммирует
стабильность, политику остановки раунда, обновление baseline, роли и проверку
соединения; он янтарный при несовместимом соединении или незавершённом
обновлении. В открытом виде показаны Settings, Roles, Connection и каждое
записанное обновление baseline. Каждое называет заменённое и новое измерения и
факт завершения; запись сама по себе не означает завершённое обновление, а
`count` обновлений показан отдельно от записей. Подробности Connection содержат
только код, код причины, метрику и записанные пути как текст.

Каждая финальная запись каждого раунда появляется один раз в порядке Core как
второй шаг попытки: строка *Final · entry K* под измеренным финалистом или при
`round_stop: all_attempts` строка *Joint final · entry K* после попыток. Строка
показывает измерение, точку, Δ относительно Champion, решение Core и *vs vN · stored*
или *re-measured*. Решение — *Accepted*, *Not accepted* или *Unavailable* с
кодом: незавершённый Core контраст (`final_incomplete`) недоступен, а не
отклонён — как и на Measurement. Открытая строка показывает порядковый номер,
стабильность, изменение условия на месте, сторону Чемпиона, сохранённое
измерение, режим/global, участников и их completion/missing/critical,
контрасты с границами, причину приёмки или недоступности, exact/pairing, число
удалённых пар/кейсов, выбор, перечисленные пары и следующий baseline. Финалист,
чей финал ещё не начался, имеет пунктирную строку *Final measurement · not started*.
Идентификаторы измерений ведут на экраны только для чтения. Эти экраны помечают
все записанные отношения финала и обновления baseline.

*Finalist* вышел в финал. Финальное решение показано отдельно; финальный выбор
или принятый контраст не устанавливает продвижение. *Champion transition*
берётся только из совпадающих записей `promoted_attempt` в доступной родословной
Чемпионов. Все записанные переходы показаны в порядке родословной и не утверждают,
что версия всё ещё текущий Champion. Отсутствующая родословная недоступна;
доступная без совпадения показывает *No transition recorded*. В раундах столбец
*Champion* строки попытки показывает `→ vN` из той же родословной, `—`, если
переход не записан, и *unavailable*, если родословная недоступна. На Measurement
это три факта панели *Decision* — *Gate*, *Final decision*, *Champion transition* —
каждый со своим пустым состоянием; при нескольких продвинутых версиях подпись
родословной называет измерение каждой версии. Исход раунда остаётся отдельным фактом.

Confidence в раундах кампании не показан; он находится на Measurement попытки.
Под Decision панель **Confidence** показывает режим один раз (`observe` с
янтарным *bounds not computed*), последнее оценённое Core look: *Accepted*,
*Rejected*, *Insufficient evidence* или *Next look*, неизменённый код причины
Core, номер look (и является ли он финальным) и margin. Строки *Focus* и
*Causal* показывают `point [lower, upper]`, индикатор exact интервала и число
кейсов, а рисунок на общей шкале — только когда записаны обе границы;
отсутствующая граница — `—`, никогда не 0. Дополнительная строка показывает
повторы и калибровку. Раскрытие *Look history* перечисляет все оценённые look
с причинами; отсутствующие границы там обозначаются *no lower bound in the view*
или *no upper bound in the view*, а look без границ показывает точку с
*no bounds in the view*. Коды `unavailable` отдельных оценок Core читайте через
`lab attempt OPERATION ATTEMPT`. Null оценка или калибровка — `—`;
`confidence: null` означает *not recorded for this attempt*, а `latest: null` —
*not evaluated yet* с повторами и числом кейсов.

**Family 15 (кампании `/16`).** Под сводкой настроек (R, режим, шум, проверка)
каждая попытка показывает исход и причину и для каждой области утверждение её
правила: «прирост; с доверием c не ниже L; порог» (`bound`), «прирост; порог»
(`point`), «прирост» с указанием отсутствия порога или статус Core без чисел.
Двусторонний интервал не рисуется. Каждое сравнение помечено «vs round Champion»
с сохранённым или свежим измерением либо «measurement not recorded»; «vs Parent»
нет. Попытка без сравнения показывает причину и факты достижимости. Панель
остаётся только для чтения. Оба записанных уровня показаны отдельными блоками
gate и global со своими исходом, причиной, решающим слоем, эталоном и областями;
отсутствующие уровни опущены. `reference_measurement_id`, совпадающий с
`measurements[].measurement_id` этого представления, ссылается на соответствующий
экран Measurement; иначе это короткий текст без дополнительного запроса.
Сравнение Measurement попытки и метки delta кампании/diff используют сравнение
gate. Отдельное финальное измерение global Кандидата не имеет метки сравнения
попытки. JSON `comparison` — global, если он есть, иначе gate; Lab копирует
все три поля сравнения независимо. Показывается только односторонняя нижняя граница.

`caveats` представления family14 показываются понятной подписью и неизменным
кодом. Ограничения кампании — в ограничениях карточки состояния; раунда и
попытки — в собственных строках янтарной меткой *N limits*, открывающей список
(те же строки есть в title метки); на измерении — в Confidence или отдельно,
если её нет. Каждая строка называет область: *Campaign*, *Round N* или
*Attempt ID · round N*. Измерение показывает ограничения кампании, своего
раунда и только своей попытки; финальные измерения не наследуют ограничения
попыток-участников. Ограничения видимы и без confidence или последнего look.
Неизвестные виды сохраняют исходный код. Эти строки не меняют решение Core или отметки gate.

`/15` содержит `family: 14 | 15`; для family 14 он полностью опускает `cohort`
и `alpha_total` попытки. Панель Confidence показывает margin и по одному
индикатору exact на интервал рядом с точкой/границей. Отсутствующие числа — `—`,
неизвестные коды остаются буквальными. Панель не делает новых утверждений о
статистических границах. Старые представления отклоняются без преобразования;
старые прогоны и состояние нужно просматривать с породившими wheel.

Для family 15 свёрнутый блок checks показывает `checks.modes`
представления и каждый счётчик `checks.shadow_hits`. Режимы и счётчики видимы,
даже когда независимая приёмка недоступна. Присутствующее null-значение checks
скрывает блок; недоступные checks показывают состояние нечитаемости. Счётчики
разных проверок несопоставимы и никогда не складываются. Панель копирует данные
Core из представления; режимы проверок отделены от уведомлений Lab.

### Текущая приостановка и история

При открытии экрана приостановленной кампании читается **Latest pause evidence**;
блок находится сразу под причиной и вердиктом продолжения. Заголовок называет
seq паузы, reason, owner и вид доказательств, затем число строк, первые 8
символов digest и полноту строк. Последнее совпадающее событие — *Current pause*;
более ранние свёрнуты под *Earlier pauses* с пометкой *Historical*. Если
доказательства там недоступны, панель сообщает, что причина всё ещё берётся из
представления кампании, и не показывает строки. Продолженная или завершённая
кампания предлагает свёрнутую **Suspension history** под карточкой состояния: сводка считает
паузы, перечисленные представлением (*N pauses recorded* или *No pauses recorded*),
ничего не читая, и говорит *loaded when opened* до открытия. Число и *No pauses recorded*
показываются только пока чтение кампании свежее; при устаревшем, недоступном,
загружающемся чтении или недоступном сервисе сводка не утверждает ничего о
паузах (старое или неудачное чтение не означает их отсутствие). После открытия
число сохраняется только пока свежее само чтение истории; иначе тело показывает
своё состояние. Текущий статус берётся из операции, поэтому старая пауза не
делает продолженную кампанию сейчас приостановленной.

Строки показывают идентификаторы измерения/кейса/образца и порядковый номер
повтора, причину и допускающий null код для ошибок оценщика или owner для строк
final/Champion. Идентификаторы измерений ссылаются на их экраны. Доказательства
порога и этапа показывают только закрытые поля; локаторы префикса байтов
остаются обычным текстом. Это строки, вызвавшие паузу, а не полный оставшийся
список работ. *Showing N of count* и `truncated` описывают возвращённый префикс;
Lab не может получить недостающий хвост.

Состояния загрузки, недоступности и устаревания применяются к истории независимо;
ошибка чтения оставляет остальной экран пригодным. Сохранённые доказательства
помечаются устаревшими после ошибки или новой известной последовательности паузы
и не подтверждают текущую причину или полноту. Изменение sequence инвалидирует
историю; открытый блок перечитывается, закрытый ждёт следующего открытия.
*No pauses were recorded* требует успешного пустого результата. Смена операции
очищает прежние данные, удаление результатов очищает сохранённую историю вместо
показа устаревшей.

### Чтение кейсов и содержимого ролей

На **Measurement** и **Evaluation** подробности выбранного кейса находятся над
таблицей (до выбора — первая строка); нажмите строку или используйте ↑/↓ для
перехода. В измерении попытки baseline и Кандидат стоят рядом, когда пара
проверена (одинаковые кейс и образец); иначе сторона baseline показывает
*Baseline not paired* с кодом. Каждая сторона показывает публичный вход,
диалог, вердикты и обратную связь оценщика. Ход показывает вход
(`message.content`) и события `assistant_message`, каждое с меткой
*Turn N · assistant_message* (и записанным именем события); все остальные
события, `message.fields` и usage хода находятся в *Technical events (n)* под
ходом, а ход без assistant message сообщает *No assistant_message in this turn*.
Неудачный оценщик может оставить диалог читаемым; его исходный вывод — приватная
диагностика, не вердикт. Отсутствующая или неполная трасса имеет явное
состояние и причину. При выборе другого кейса или измерения подробности снова публичны.

**Show private content** перечитывает содержимое с `?disclose=private`: тогда
появляются эталон/oracle, диагностика/details оценщика и примечания вердикта.
Только эти приватные части берутся из приватного чтения: ходы, вход, оценивание
и терминальный вывод остаются из публичного, поэтому слишком большая часть
одного ответа не скрывает возвращённое другим. Выбор не запоминается. Карточка
Reflector использует такую же явную кнопку для приватного текста и перечитывает
рефлексию. **Не передавайте `--disclose-private`, `?disclose=private` или
раскрытые эталон/диагностику в контекст редактирующей модели. Core скрывает
эталон от неё; раскрытие предназначено для просмотра человеком**.

Измерение попытки имеет карточки **Reflector** и **Editor**: упорядоченные
события, вызовы/результаты инструментов при наличии, изменённые файлы или их
записанное число, коды/текст ошибок. `agent_cli` не записывает вызовы
инструментов; карточка показывает сводку. Subprocess-роли имеют только хвост
stderr, если записан. `[REDACTED]` показывается как получен с подсказкой о
скрытых рассуждениях и маскировании ключей. Usage ролей, токены Editor/оценщика
и деньги не показаны. `agent_cli` покрыт только unit-примерами, не контрактным
тестом реального прогона.

**Look history** перечисляет все оценённые look попытки с решением, причиной
Core и частичными интервалами; она дополняет последний look панели Confidence.
Кампания показывает максимум первые 400 символов ошибки. Если у попытки есть
измерение, его карточка Editor показывает весь предоставленный текст ошибки
(с учётом лимитов ответа). У попытки `editor_failed` без измерения нет страницы
измерения; используйте `lab attempt O ATTEMPT` для её содержимого.

Секции содержимого показывают недоступность и причину (включая `too_large`)
рядом с секцией. Видны `masking: keys`, `truncated`, число пропущенных записей
и пути обрезанных полей с исходным размером в символах. Маскирование ключей не
сравнивает текст с реальными значениями секретов. Исходные размеры считаются
после маскирования, до обрезки. Общий предел ответа — 1 МиБ с уровнями
текста/списков 16,384/200 → 4,096/100 → 1,024/40, затем самые большие
разрешённые секции заменяются явными объектами unavailable/too_large.
Публичные приватные поля остаются скрытыми и при переполнении; см.
[точные варианты API и метаданные](../../../lab/docs/api/owner-s4.md#sample-attempt-and-reflection-content).
Лимиты предварительные до пилота track E на реальных трассах; небольшой снимок
демо доказывает соединение компонентов, а не пригодность к реальным трассам.
История попыток оценивания и неполное содержимое ролей не показываются.

### Содержимое оценщика на точной dev61/b13

Эти гарантии чтения появились в dev61/b13. Имена схем ниже относятся к текущим исходникам dev79;
исторические запуски сохраняют свои producing-пары.

Lab использует публичный `ScorerTraceReader` Core для трасс каталогов и pack,
адресованных выбранными измерением и запросом оценивания. Завершённые записи
журнала по-прежнему ограничивают раскрытие и определяют состояние оценивания;
проверки identity/hash, `lab-sample/1`, кампания `/15` с family 14 и 15,
приватное раскрытие и маскирование ключей сохраняют текущий контракт.
Отсутствующие записи — `trace_missing`; неизвестные размеры запроса —
`trace_missing` для pack и консервативно `unreadable` для каталогов.
Проверенные вход/диалог сохраняются при отсутствии stdout с `trace_missing`
(pack) или `unreadable` (каталог), даже при ошибке оценивания. Пустой stdout
неудачи остаётся доступным; допущенное оценивание всё ещё требует корректный
JSON. Ошибка чтения payload не сохраняет непроверенный вход. Существующий
приватный `exit_status` неудачного оценщика может содержать returncode Core;
трассы каталогов дают null. Stderr не читается.

На каждый запрос открывается один `ScorerTraceReader(root, run_boundary="nofollow")`
Core. Метаданные (`sections=()`) и payload используют тот же reader; чтение
payload передаёт `max_section_bytes=33554432`. Метаданные запроса/stdout и
возвращённые байты также проверяются до разбора/раскрытия. Превышение размера
отклоняет всю трассу как `too_large`, без частичного входа. Типизированный
`too_large` отображается в этот код; другие типизированные ошибки чтения — в
`unreadable`. Stderr не запрашивается.

Строгий обход без перехода по ссылкам и ограниченное чтение payload заменяют
прежние исключения b5 root-swap/file-growth. Лимит секции не ограничивает весь
индекс pack или RSS процесса и не делает файлы неизменяемыми для владельца. Это
остаточное ограничение явно принято для точной dev54/b6 (отдельно, как и для
локальной dev53/b6 ранее); ни один последователь, включая Lab-only repin, не
наследует приёмку автоматически. Для точной dev56/b8 пользователь отдельно
принял его 2026-10-20. Для точной dev57/b9 — отдельно 2026-10-20; приёмка dev56
не перенеслась. Для точной dev58/b10 — отдельно 2026-10-22; приёмка dev57 не
перенеслась. Для точной dev59/b11 — отдельно 2026-10-23; приёмка dev58 не
перенеслась. Модули чтения Core неизменны: nofollow и 32 МиБ на выбранную
секцию сохраняются без общего лимита индекса pack/RSS и неизменяемости файлов
владельца. Для точной dev60/b12 пользователь отдельно принял то же ограничение
2026-10-25; приёмка b11 не перенеслась. Каждая следующая пара требует отдельной
оценки. Старые пары/прогоны остаются в породивших окружениях; автоматического
завершения или миграции нет.

Для точной dev61/b13 пользователь условно принял это ограничение 2026-10-27 по
ADR-0019. Аудит точного тега подтвердил неизменность модулей чтения/хранения,
поэтому условие выполнено: nofollow и 32 МиБ на выбранную секцию остаются без
общего ограничения индекса pack/RSS и неизменяемости файлов владельца. Это
отдельная приёмка; приёмка dev60/b12 не перенеслась. Она не разрешает выпуск,
миграцию или создание состояния.

Содержимое, которое Lab ещё не читает, помечено *Not read by Lab yet*. Число
токенов Editor помечено *Not shown in panel v1* согласно PDR-0017.

По умолчанию тема тёмная. Переключатель внизу боковой панели меняет её и
запоминает в браузере (`localStorage`); если браузер отказывает в хранении,
страница работает и в следующий раз начинает с тёмной темы. Шрифты Geist
поставляет сама панель, поэтому интернет странице не нужен.

| Путь | Что это |
|---|---|
| `<home>/panel.json` | Запись работающей панели (`lab-panel-runtime/1`), права `0600`. Записывается, когда панель слушает; удаляется при корректной остановке. |
| `<home>/panel.lock` | Блокировка, показывающая, что панель жива. Свободная блокировка означает отсутствие панели независимо от `panel.json`. |
| `<home>/logs/panel.log` | Вывод панели `--background` (каталог `0700`, файл `0600`). Содержит ссылку запуска **с токеном** — обращайтесь с ним как с `panel.json`. |

Это единственные три объекта, которые панель пишет в home. Если каталог home
отсутствует, она создаёт только его (`0700`); никогда не создаёт `clones/`,
`workspaces/` или что-либо ещё и не следует символическим ссылкам: путь home
через ссылку, `logs` как ссылка или `panel.log` как ссылка отклоняются с
`home_invalid`. `lab panel status` и `lab panel stop` следуют тому же правилу
(и никогда не создают home; максимум — собственный `panel.lock`), поэтому
`stop --home <symlink>` не достигает панели за ссылкой.

### Когда сервис недоступен

Если панель не может связаться с сервисом — он не запущен, перезапущен или
слишком медленен, — пересланный запрос отвечает `503 service_unavailable` с
подсказкой `lab serve --home <home>`. Страница показывает это двумя способами:
карточка health сбоку становится янтарной (*Service unavailable*), а баннер
над экраном сообщает *Lab service unavailable — start it with `lab serve --home <home>`*.
Если перестаёт отвечать сама панель, баннер спрашивает, работает ли ещё
`lab panel`. Открытая страница перепроверяет сервис каждые 5 секунд и сразу при
обрыве живого потока, поэтому сбой после загрузки показывается вместо замершей
страницы; каждый экран сохраняет последний ответ с пометкой *stale · last answer shown*
(в том числе прочитанный один раз, например карточку операции). Запустите или
перезапустите `lab serve` для home: за 5 секунд баннер исчезнет, страница
перечитает данные всех экранов и переоткроет поток; перезапуск панели не нужен.
Такое же перечитывание происходит, когда сама панель снова отвечает после
остановки, включая случай отсутствия ответа на первую проверку страницы.

### Ошибки CLI

Ошибки `lab panel` печатают JSON в stderr и завершаются с кодом 1, например
`panel_already_running`, `panel_port_in_use`, `panel_dependencies_missing`,
`panel_start_failed` (подробности в журнале), `panel_start_timeout` (содержит
`pid` потомка), `panel_identity_unconfirmed` (`stop` не посылает сигнал процессу,
не доказавшему принадлежность этой панели). Полный список — в [API](../../../lab/docs/api/panel.md#cli-errors).

### Безопасность

- Панель слушает только `127.0.0.1`.
- Каждый запрос должен содержать правильный `Host` — ровно
  `p<random>.localhost:<port>` этого запуска; `127.0.0.1:<port>` и
  `localhost:<port>` отклоняются с 421 — и сессионную cookie, полученную по
  ссылке с токеном. Это блокирует другие машины и страницы с DNS rebinding.
- Cookie имеет `HttpOnly; SameSite=Strict`; каждый ответ содержит
  `Cache-Control: no-store`, Content Security Policy `default-src 'self'`,
  `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`.
- Зачем случайное имя хоста: браузеры не изолируют cookie по порту, поэтому
  cookie для `127.0.0.1` отправлялась бы каждому другому посещённому HTTP-серверу
  на `127.0.0.1`, передавая ему токен. Cookie ограничена хостом (без атрибута
  `Domain`) с именем, которое не использует другой сервер, поэтому возвращается
  только этой панели (ADR-0018 п. 3, с поправкой).

### Удалённый доступ

Не поддерживается. Панель отклоняет любой `Host`, кроме своего loopback-имени и
порта. Если вы всё же пробрасываете порт через SSH-туннель, делаете это на свой
риск; браузер всё равно должен обращаться к `p<random>.localhost:<port>`
(напечатанная ссылка) с тем же номером порта с вашей стороны.
На хосте с включённым SELinux `sshd` может пробрасывать только порты с разрешённым
для соединения типом SELinux; свободный порт панели по умолчанию обычно к ним не
относится. Запустите панель с `--port <an allowed port>` вместо изменения политики.

### Запуск как модуля

`python -m evolution_lab.cli panel …` — та же команда, что `lab panel …`
(фоновый запуск использует её для отсоединённого потомка).
