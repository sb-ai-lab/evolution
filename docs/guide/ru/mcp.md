# Подключите кодинг-ассистента к Lab по MCP

[English](../mcp.md) · Русский

Готовые навыки Evolution доступны в своём репозитории после [сборки и установки плагина](../../../plugins/README.md#build-and-install). Эта страница про доступ к локальному сервису Lab. Если вы работаете в своём репозитории, [подключите плагин к Lab](#подключение-через-плагин). Для других MCP-клиентов есть [ручная настройка](#запуск-из-клиента).

## В рабочем пространстве проекта Lab

Если хотите, чтобы Lab открыл отдельное рабочее пространство для зарегистрированного проекта, выполните эти шаги. Они подходят для Claude Code, Codex, Qwen Code и GigaCode CLI.

1. Если Lab ещё не установлен, выполните `just setup` в каталоге `lab/` репозитория Evolution. [Что нужно для установки](install.md). Запустите локальный сервис командой `just serve` и оставьте его работать.

   Если вы установили Lab из wheel, [запустите сервис командой `lab serve`](projects.md#перед-началом) в окружении с зависимостями `[service,mcp]`. В следующих шагах используйте `lab` вместо `just lab`.

2. Во втором терминале в каталоге `lab/` узнайте ID проекта.

   ```sh
   just lab --json project list
   ```

   Чтобы попробовать настройку на офлайн-демо, выполните `just lab project demo demo` и используйте ID `demo`.

3. Откройте проект, подставив его ID.

   ```sh
   just lab project open ID --autonomy ask
   ```

4. Запустите ассистента в каталоге, который напечатала команда. Если клиент спросит, одобрите сервер `evolution-lab` или подтвердите доверие к рабочему пространству. Попросите ассистента вызвать `health` и `guides_list`. Вы увидите версию Lab и список установленных руководств.

### Как настроено подключение

Клиент использует Python и сокет того сервиса Lab, который открыл рабочее пространство. В Lab dev79 по MCP можно подготовить входные данные, запустить или продолжить кампанию. Проверьте, есть ли среди инструментов `operation_start`.

Если в окружении сервиса установлены зависимости `[mcp]`, Lab пишет следующие файлы.

| Файл | Клиент |
|---|---|
| `.mcp.json` | Claude Code |
| `.codex/config.toml` | Codex |
| `.qwen/settings.json` | Qwen Code |
| `.gigacode/settings.json` | GigaCode CLI |

Каждый объявляет сервер `evolution-lab`. Его команда — интерпретатор сервиса,
который записал рабочее пространство, а аргументы —
`-E -P -m evolution_lab.cli mcp --socket SOCKET --autonomy LEVEL`: сокет задан явно, поэтому
рабочий каталог и `LAB_HOME` не важны. Для того же сервиса, проекта и
установки и режима файлы побайтово одинаковы. Lab ничего не пишет вне рабочего
пространства и не записывает настроек доверия или одобрения.

- **Одобрение.** Действуют собственные правила одобрения клиента, а Lab никогда
  не одобряет сервер и не объявляет его доверенным за вас. Интерактивные Claude
  Code, Qwen Code и GigaCode CLI один раз спросят, одобрить ли сервер проекта;
  неинтерактивные режимы, например `claude -p`, загружают серверы проекта без
  вопроса. Если спросят, одобрите и проверьте, что инструменты
  отвечают: например, `claude mcp list` показывает `evolution-lab`, а
  инструмент `project_status` ассистента возвращает состояние проекта.
  GigaCode CLI построен на Qwen Code, поэтому Lab считает расположение его файла
  (`.gigacode/settings.json`) и поведение одобрения такими же, как у Qwen Code.
  Это допущение, пока его не подтвердит живая сессия GigaCode; если сервер там не
  появился, так и скажите.
- **Codex.** Codex читает проектный `.codex/config.toml` только в каталоге,
  которому вы доверяете. Он спросит при запуске в этом каталоге; либо добавьте
  запись доверия для рабочего пространства в свой `~/.codex/config.toml`. Lab
  эту запись не пишет. На офлайн-проверке Codex CLI 0.171.0 загрузил сервер в
  доверенном рабочем пространстве без Git-репозитория. Если сервер не появился,
  используйте команды CLI из `AGENTS.md` рабочего пространства.
- **Без extra.** Если `mcp` не установлен в диапазоне extra (`>=2.3,<3`) там, где работает `lab serve`,
  ни один из четырёх файлов не пишется, а `AGENTS.md` сообщает «Lab tools are
  not configured». В чекауте Lab снова выполните `just setup`; при установке из
  wheel переустановите wheel Lab с `[service,mcp]` в окружении `lab serve`;
  затем снова выполните `lab project open ID`.
- **После повторного open или обновления.** Работающий сервер хранит то, что
  прочитал при старте. После того как `lab project open` пересоздал рабочее
  пространство, а сервис на этом сокете перезапустили или обновили,
  перезапустите сессию ассистента в рабочем пространстве или переподключите
  сервер `evolution-lab`, если клиент это позволяет. После обновления или
  переноса Lab, а также после запуска сервиса на другом сокете снова выполните
  `lab project open ID` с нужным `--autonomy`.

В `AGENTS.md` записан выбранный режим. Команды CLI используют абсолютный путь
к интерпретатору сервиса, аргументы `-E -P -m evolution_lab.cli` и явный `--socket`.

Ограничения сгенерированной конфигурации:

- Рабочее пространство настраивает сервер, только если `mcp` — финальный релиз
  в диапазоне `>=2.3,<3`; pre-release, dev и локальная сборка считаются
  отсутствующими, и `AGENTS.md` несёт уведомление «не настроено».
- Python читает `PYTHONUSERBASE` даже с `-E`. Если Lab установлен через
  `pip install --user` с нестандартным `PYTHONUSERBASE`, которого нет у
  клиента ассистента, сервер не запустится. Запасной вариант через CLI в
  `AGENTS.md` использует тот же интерпретатор и падает так же, поэтому нужна
  среда, где Lab импортируется: тот же `PYTHONUSERBASE` у клиента или установка в
  venv.
- Claude Code раскрывает `${VAR}` в `.mcp.json`. Если команда сервера или любой
  аргумент содержит `$`, Lab не пишет `.mcp.json`; остальные три файла
  записываются, а `AGENTS.md` сообщает, что Claude Code не настроен, и отправляет
  к запасному варианту через CLI.

## Подключение через плагин

Если вы работаете в своём чекауте, соберите пакет Qwen Code, GigaCode CLI или Agent Plugins v1.
Укажите абсолютный путь к Python из окружения Lab, сокет сервиса и режим `ask` или `yolo`.
Сервер MCP и команды Lab из инструкций плагина используют это подключение и этот режим.

После установки попросите ассистента вызвать `health` у сервера `evolution-lab-plugin`.
В рабочем пространстве Lab используйте его сервер `evolution-lab`. Для настроенного переносимого
плагина заведите отдельный профиль Codex или Hermes. [Сборка и подключение плагина](../../../plugins/README.md#connect-a-plugin-to-lab).

## Автономия и подтверждение действий

- **`ask` (по умолчанию).** Для затратных, необратимых действий и решений от имени человека Lab запрашивает
  подтверждение. Если клиент объявил поддержку форм, Lab показывает форму. Иначе действуют правила
  одобрения инструментов клиента. При работе через CLI ассистент спрашивает в разговоре и выполняет
  команду после согласия.
- **`yolo`.** Lab выполняет запрошенное действие без формы. Собственные правила клиента продолжают действовать.

Чтобы сменить режим, снова выполните `lab project open ID --autonomy ask` или
`lab project open ID --autonomy yolo` и перезапустите сессию либо переподключите сервер.
Для плагина пересоберите пакет с нужным `--autonomy` и переподключите клиент.
При ручном запуске задайте режим аргументом `lab mcp --autonomy`.

В форме указаны действие, объект и состояние, к которому относится согласие. Для запуска она
показывает ожидаемые вызовы, когда их можно вывести из плана, лимит шлюза или
`no Lab spending limit`, и доступные автостарты. Шлюз ограничивает только вызовы через него.
Отказ, отмена или истечение `--approval-timeout SECONDS` (по умолчанию 600) оставляют действие невыполненным.
Сервис сверяет показанное состояние при допуске действия.

На MCP до `2025-11-25` включительно форма запрашивается во время вызова. Начиная с `2026-07-28`
клиент возвращает ответ следующим вызовом. Если факты изменились, Lab показывает обновлённую форму.

Клиент может сначала спросить разрешение на вызов инструмента, а затем показать форму Lab.
Мы проверили запуск офлайн-кампании в режиме `ask` в обоих клиентах.

- Claude Code 2.1.331 показал форму в терминале. После отказа кампания осталась незапущенной,
  после подтверждения запустилась. В `claude -p` клиент отклонил вызов.
- Codex CLI 0.171.0 показал форму в интерактивном режиме `on-request`, в том числе когда
  автоанализ допустил вызов инструмента. В обоих режимах кампания запустилась после подтверждения
  человека. С автоанализом отказ оставил кампанию незапущенной. В `codex exec` клиент блокировал
  вызов либо отменял форму после допуска вызова автоанализом.

Lab ориентируется на объявленные возможности клиента. Для Qwen Code и GigaCode без форм применяются
правила клиента, поэтому автоматический режим может выполнить вызов без участия человека.
В записи одобрения `form` означает принятый ответ формы, `client_rules` — правила клиента,
`none` — режим `yolo`. Записи доступны через `lab approvals --operation OP` и `lab project approvals ID`.

Подготовка, проверки, conformance, запуск целей и остановки обходятся без вопроса Lab. Проверки
и conformance рассчитывают, что адаптер отвечает офлайн. Если он передаёт эти вызовы платной модели,
затраты возможны без вопроса Lab. Значения секретов передавайте через `secrets_file`, абсолютный
путь к JSON-файлу. Форма показывает только имена секретов.

## Запуск из клиента

Так сервер регистрируют вручную: для клиента без сгенерированного файла или
вне рабочего пространства.

Зарегистрируйте stdio-сервер: команда `lab`, аргументы `["mcp"]`:

```json
{"command": "lab", "args": ["mcp"]}
```

В чекауте `lab` не лежит в `PATH`; в качестве команды укажите абсолютный путь к
скрипту окружения Lab:
`{"command": "/path/to/evolution/lab/.lab/venv/bin/lab", "args": ["mcp"]}`.

Чтобы закрепить сокет: `{"command": "lab", "args": ["mcp", "--socket", "/path/to/service.sock"]}`.
Другой способ выбрать его — `--home DIR`; `--timeout SECONDS` ограничивает каждый
вызов инструмента (по умолчанию 60): обмен с сервисом и собственные ожидания
сервера. Разбор и проверка уже полученного ответа могут ненадолго выйти за этот
предел. `--socket` и `--home` принимают абсолютные
пути; относительный путь отклоняется.

## Какой сервис он читает

Сокет выбирается как у любого адаптера: `--socket`, иначе `--home`, иначе домашний
каталог Lab по умолчанию (`LAB_HOME`, иначе `$XDG_DATA_HOME/evolution-lab`), внутри
него `service.sock`. Рабочий каталог не учитывается: если `LAB_HOME` или
`XDG_DATA_HOME` относительный, `lab mcp` завершается с кодом 2 и сообщением
`usage: socket path must be absolute`. Инструкции сервера называют
выбранный сокет. `lab mcp` не запускает сервис: сначала запустите его командой
`lab serve --state DIR`, затем вызовите `health`.

## Инструменты

Непустым должен быть идентификатор, который
становится частью пути запроса (проект, операция, замер, кейс, сэмпл, попытка,
рефлексия, дайджест, цель, задача, сценарий, схема, имя руководства). Фильтр или
другой аргумент запроса (`implementation`, `scenario` у `project_status`, `path`,
`bundle`, `owner_generation`, `tree_from`, `tree_to`, `file` руководства)
передаётся как есть, в том числе пустая строка, и сервис (или чтение
руководства) отвечает на него так же, как в CLI. Идентификаторы берутся из списочных инструментов; описание каждого аргумента
говорит, из какого.

| Группа | Инструменты |
|---|---|
| Сервис | `health`, `scenarios_list`, `scenario_show`, `scenario_schema`, `requirements` |
| Операции | `operations_list`, `operations_summary`, `operation_status`, `operation_failure`, `operation_refusal`, `operation_inputs`, `operation_routing`, `operation_suspensions` |
| Отчёты | `operation_report`, `operation_report_markdown`, `operation_campaign` |
| Замеры и деревья | `operation_measurements`, `operation_measurement`, `operation_sample`, `operation_attempt`, `operation_reflection`, `operation_diff` |
| Проекты | `projects_list`, `project_show`, `project_status`, `project_facts`, `project_confirmations`, `project_tree`, `project_operations`, `project_operations_summary` |
| Bundle и политики | `bundle_show`, `bundle_measurements`, `prepared_show`, `execution_policies_list`, `execution_policy_show` |
| Цели и задачи | `targets_list`, `target_status`, `task_status` |
| Руководства | `guides_list`, `guide_read` |

`project_tree` принимает `path` относительно дерева; корень — `.`. Инструменты
руководств и ресурсы руководств работают без сервиса.

| Действия | Инструменты |
|---|---|
| Подготовка и цели | `bundle_create`, `prepare`, `connect`, `target_start`, `target_stop`, `check`, `conformance` |
| Операции и задачи | `operation_start`, `operation_resume`, `operation_stop`, `task_stop`, `delete_results`, `release`, `cleanup` |
| Проекты | `project_bundle`, `project_prepare`, `project_target`, `project_start`, `project_sync_check`, `project_sync`, `project_confirm`, `project_accept_preview`, `project_accept_commit`, `project_revoke_confirmation`, `project_revoke_acceptance` |
| Политики и одобрения | `policy_confirm`, `approvals_list`, `project_approvals` |

Изменяющие инструменты принимают `request_id` и `owner_generation` из выбранного сервиса
(поколение возвращает `health`). При повторе сохраните оба ключа и аргументы. Если после перезапуска
сервера пересобранный запрос отличается, сервис может вернуть `request_conflict` или отказ из-за
изменившегося состояния. После `acceptance_unknown` сначала прочитайте состояние.

## Руководства как ресурсы

Установленные руководства доступны и как ресурсы MCP: `lab://guides/<name>/SKILL.md`
для каждого руководства, `lab://guides/scenarios/<id>/SKILL.md` для руководства
каждого сценария и шаблон `lab://guides/{name}/{file}` для остальных файлов
руководства. `lab://guides/<name>` читает его `SKILL.md`.

## Уведомление о версии

При старте `lab mcp` один раз читает `health` в пределах меньшего из `--timeout` и
5 секунд. Если `lab_version` сервиса отличается от установленного `evolution-lab`,
инструкции сервера и каждый результат инструмента руководств сообщают об этом:
руководства описывают установленную версию, а не версию сервиса. Инструкции
относятся и к ресурсам руководств; чтение ресурса собственного уведомления не
несёт. Это чтение берёт `lab_version` из любого ответа `health`, даже другой
версии схемы; сам инструмент `health` схему по-прежнему проверяет. Если чтение
при старте не удалось, первый вызов руководства пробует ещё раз, не дольше
половины своего `--timeout` и 5 секунд; прерванное чтение уведомления не
добавляет, и результат руководства приходит без него.

## Ошибки

Неудачный вызов возвращает конверт CLI, `{"error": {"code", "stage", "message"}}`
с необязательным `hint`, как структурированный результат и как JSON-текст, с
признаком `isError`. Ошибки сервиса проходят целиком. Коды, которые добавляет сам
`lab mcp`:

| Код | Стадия | Когда |
|---|---|---|
| `request_timeout` | transport | Вызов не завершился за `--timeout`: запрос к сервису или чтение руководства. Повторите. |
| `request_interrupted` | transport | Соединение оборвалось во время запроса. Повторите. |
| `acceptance_unknown` | transport | При обмене с сервисом потерян результат мутации. Прочитайте состояние перед повтором. |
| `service_unavailable` | client | На сокете нет сервиса. Подсказка велит запустить его и называет сокет. |
| `invalid_service_response` | client | Ответ не соответствует схеме. Сервис Lab и `lab mcp` могут быть разных версий. |
| `usage_error` | client | Аргумент пропущен, неизвестен, неверного типа или это некорректный идентификатор. Проверка по входной схеме инструмента идёт до любого запроса; затем декодеры идентификаторов отклоняют некорректный идентификатор (`a/b`, неверный дайджест, неизвестное руководство или сценарий). |
| `internal_error` | client | Неожиданный сбой внутри `lab mcp`; сообщение общее. |
| `approval_declined`, `approval_cancelled`, `approval_failed`, `approval_timeout` | approval | Форма не дала действительного согласия. Запрос действия не отправлен. |
| `request_conflict` | approval | В этой сессии тот же ключ уже использован с другими аргументами. |

## Чего он не делает

- Нет раскрывающих чтений и диалогов пробы; они остаются в CLI.
- Не запускает сервис.
- Только stdio: ни HTTP, ни удалённого транспорта.
- Нет промптов, sampling и URL-форм MCP.

О сервисе и остальных командах — [CLI и локальный сервис](cli.md).
