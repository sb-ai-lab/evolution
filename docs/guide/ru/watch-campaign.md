# Наблюдение за кампанией

[English](../watch-campaign.md) · Русский

Кампания может длиться сутки и дольше. Эта памятка поможет следить за ней из
терминала: какую команду оставить работающей, что означают строки вывода и что
делать после остановки.

## Команды

| Команда | Для чего нужна |
|---|---|
| `lab watch OPERATION` | Основной способ: сначала снимок, затем строка на каждое изменение; команда завершается, когда операции требуется ваше участие или она закончилась. |
| `lab status OPERATION` | Однократный просмотр операции: состояние управления, `progress:`, приостановка с `hint:` и `continuation:`. |
| `lab campaign OPERATION` | Однократный просмотр кампании: исход, gate, раунды и попытки. |
| `lab list --summary` | По строке на операцию: id, вид, состояние, фаза, исход. |
| `lab report OPERATION --markdown [--output FILE]` | Отчёт прогона одним Markdown-файлом (`report.md`), который можно сохранить или переслать. |

`lab watch` читает статус `lab-operation-status/7` и представление кампании
`lab-campaign-view/11`: как family 14 (манифест `/15`), так и family 15
(манифест `/16`). В ленте используется тот же текст, что в `lab campaign` и
`lab status`.

Все команды, как обычно, принимают `--socket` или `--home` ([CLI](cli.md#глобальные-флаги)).

## Оставить команду работающей

```bash
lab watch OPERATION                                # in a terminal you keep open
nohup lab watch OPERATION >> watch.log 2>&1 &      # in the background; follow it with: tail -f watch.log
lab watch OPERATION | tee -a watch.log             # on screen and in a file
```

Каждая строка выводится сразу, поэтому `tail -f` и `tee` показывают её без
задержки. `--interval SECONDS` (по умолчанию `10`) задаёт, насколько часто
можно повторно читать представление кампании; изменения статуса печатаются
немедленно. Если статус пришёл внутри интервала, по его окончании выполняется
одно отложенное чтение, даже когда поток событий молчит; дальнейшие изменения
статуса до этого момента используют то же чтение. `lab watch` только читает:
его остановка (`Ctrl-C`, код выхода `130`) не останавливает операцию. После
`lab resume` запустите `lab watch` заново.

## Как читать ленту

Строки family 15 имеют стабильные ключи `ind:<round>:<attempt_id>:gate` и
`ind:<round>:<attempt_id>:global`; для каждой области используется
`ind:<round>:<attempt_id>:<gate|global>:scope:<name>`. Старого ключа
`…:comparison` больше нет. Уровень выводится только если он записан, со своей
причиной, решающей областью и ссылкой на Чемпиона раунда (stored/fresh/unknown
и короткий `reference_measurement_id`, если он есть). В JSON `comparison` —
это global, если он есть, иначе gate; Lab копирует все три поля независимо.

В первой строке указаны операция, её вид, номер запуска, локальная дата и
время. Ниже без времени идут текущие строки `lab campaign` (для оценки их нет),
затем строка `progress:`. После этого каждая строка начинается с локального
времени `HH:MM:SS`; печатаются только новые или изменившиеся строки. Об
исчезнувшей строке не сообщается.

| Строка | Значение |
|---|---|
| `progress: …` | Как в `lab status`: фаза, текущий/планируемый раунд, завершённые+работающие/планируемые попытки, оценённые/ожидаемые образцы. Для оценки — `progress: scored s/e`. |
| `outcome:`, `gate:`, `settings:`, `connection:` | Заголовок представления кампании, как в `lab campaign`; `gate:` только для family 14. `outcome: -` означает, что окончательного исхода Core ещё нет. |
| `round N …`, `  <attempt id> …` | Новая или изменившаяся строка раунда или попытки: новая попытка, её группа и причина Core, проверка gate, итоговое решение. |
| `independent: …`, `  gate …`, `  global …`, `  <scope>: …`, `round N preflight …`, `  preflight …`, `  eligible final score …` | Настройки family 15 и отдельные записанные строки сравнения gate/global, области, предварительной проверки и итоговой оценки; выводится только изменившаяся строка. |
| `refused: <code> …` | Core отклонило наблюдаемый запуск. Финальный статус содержит код, путь и класс; статус другого запуска не может дать эту строку. |
| `no candidate was measured: …` | Уведомление Lab рядом с исходом Core. |
| `start N` | Операцию продолжили: новый запуск. |
| `--- YYYY-MM-DD` | Начался новый местный день. |
| `campaign view unavailable: <code>` | Представление кампании сейчас недоступно; сразу после запуска, пока журнал Core не читается, это `not_found`. Наблюдение продолжается по статусу, чтение повторяется через `--interval` секунд даже без нового статуса, при переподключении или при финальном чтении. |
| `reconnecting: <code>` … `reconnected` | Соединение с сервисом прервалось (перезапуск, `service_stopping`, конец потока) и восстановилось. Изменения за этот промежуток показываются одной разницей. Через десять минут безуспешных попыток команда завершается с кодом `1` (`interrupted_observation`); запустите её снова. |
| `start M began after start N ended — run lab watch again` | Операцию продолжили сразу после её завершения; эта команда показывает только запуск N. |
| `final read unavailable: <code>` | Последнее чтение статуса не удалось, поэтому в сводке нет строк приостановки или исхода; прочитайте `lab status`. |
| `watch ended: <class> start N exit <code>` | Последняя строка, если выведена сводка. Класс — `finished`, `suspended`, `abnormal` или `unknown` (код выхода `1`, если после ошибки финального чтения класс неизвестен). При постоянном отказе, исчерпании переподключений, тайм-ауте или `Ctrl-C` команда может завершиться без сводки. |

## Когда команда останавливается

| Код выхода | `watch ended:` | Что делать |
|---|---|---|
| `0` | `finished` | Прочитайте результаты: `lab campaign`, `lab report --markdown`, [Результаты](results.md). |
| `3` | `suspended` | Core приостановило кампанию. Строки `suspended: <reason> (owner=…, evidence=…)`, `hint: …` и `continuation: …` объясняют, что исправить и как продолжить. Исправьте проблему, выполните команду из `continuation:` (`lab resume …`), затем снова запустите `lab watch`. Подробнее: [Приостановка](campaign.md#приостановка). |
| `4` | `abnormal` | Прогон завершился нештатно. Строка `abnormal:` перечисляет причины, а `hint:` даёт следующую команду; см. ниже. |
| `1` | `unknown` или нет строки | Сервис отказал в чтении (операция неизвестна или её результаты удалены; ошибка выводится в stderr), десять минут не было соединения либо последнее чтение не удалось и класс неизвестен. |
| `2` | — | Ошибка использования: `--json` (для JSON-кадров используйте `lab events`) или `--interval` меньше 1. |
| `124`, `130` | — | Истёк тайм-аут запроса (`--timeout`) или вы нажали `Ctrl-C`. Операция продолжается. |

### Код выхода 4: причины

Строка выглядит так: `abnormal: control_state=<state> target_cleanup=<state> failure=<code|-> persistence=<state>`.
Строка `hint:` соответствует первой причине в следующем порядке:

- **Очистка Target Service не подтверждена** (`control_state=orphaned` или `cleanup_required`,
  либо `released` без подтверждённой очистки): `hint: run lab cleanup operation <id>, then read lab status <id>`.
  Очистка останавливает то, что осталось после прогона; пока она не подтверждена,
  продолжить кампанию нельзя. Подробнее: [Устранение неопределённостей](results.md#шаг-5-разрешите-оставшуюся-неопределённость).
- **Операция завершилась ошибкой** (`failure=<code>`): `hint: the operation failed (<code>); read lab status <id> and lab report <id>`.
  Статус называет этап с ошибкой; отчёт показывает, что Core успело записать.
  При `failure=core_refused` строка `refused: corpus_inside_role_workspace …`
  (или другой записанный код отказа) указывает причину Core. Прочитайте код и
  путь в `lab status` и исправьте отклонённый вход перед продолжением. Если
  состояние управления также `cleanup_required`, приоритет имеет подсказка
  очистки выше; строка `refused:` всё равно объясняет отказ.
- **Результат не сохранён** (`persistence=failed`): `hint: the result was not saved (persistence failed); read lab status <id>`.
  Прогон мог закончиться, но Lab не смог записать результат:
  [Persistence: сохранён ли результат?](results.md#сохранение-сохранён-ли-результат).

## Сохранить отчёт

`lab report OPERATION --markdown --output /home/you/out/report-OPERATION.md`
записывает отчёт прогона (исход Core, gate, уведомления Lab, раунды и попытки,
корпус) в новый файл с правами `0600`; существующий файл не перезаписывается.
Без `--output` команда печатает текст. Панель предлагает тот же файл через
**Download report (.md)**. Для работающей кампании отчёт содержит то, что уже
прочитано.

## Авторизованное и связанное продолжение

Для проекта используйте `lab campaign DIR --continue`, после завершения — `lab campaign DIR --from OPERATION`; передайте установленные wheel. Отказ показывает все findings Core и команды Lab. `--accept CODE:DIGEST --reason TEXT` принимает названные findings последнего запуска; `--effect` выбирает предложенный Core эффект. Другой подготовленный вход выбирается явно через `--prepared ID`. Статус показывает текущий digest и изменения истории входов по запускам, Markdown-отчёт сохраняет эту историю. Сервисные формы — `lab resume OPERATION --accept ... --reason ...` и `lab start PREPARED --linked-from OPERATION` с обычными target/generation/secrets. JSON-статус остаётся `/8`. Подробнее: [Продолжение и связанные кампании](campaign.md#продолжение-и-связанные-кампании).
