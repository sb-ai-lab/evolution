# Using Evolution from AgentLab

AgentLab supplies the conversations, scoring rubric, selected hypotheses and experiment schedule. Evolution groups the observations, investigates a problem, prepares a prompt change and compares the measurements. AgentLab starts each stage with the Python interpreter that has Evolution installed.

## Install and check the connection

From an Evolution checkout, run the following commands on Linux or macOS. The probe works offline.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install '.[tree]'
echo '{"protocol":"agentlab-evolution/1","stage_id":"probe","operation":"capabilities"}' | python -I -m evolution.agentlab_protocol
```

Expect `status` to be `ok` and `result.operations` to list the four stages below. Point AgentLab at this environment's Python interpreter. Configure the model endpoints and credentials in AgentLab for the stages that call models. Grouping, reflection and editing use OpenAI-compatible tool calls. Comparison takes the scored measurements from the caller.

## Stage protocol

Supply one JSON object on stdin and read one JSON object from stdout. Each response echoes `protocol` and `stage_id`. A successful response contains `result`. A failure contains `error` and an optional reason code. `capabilities` reports the package version and a `runtime_sha256` fingerprint of the installed Evolution code and resources. Store that fingerprint with the run and check it when resuming. Installation paths and generated bytecode do not affect it. To recheck a run that explicitly recorded a wheel, pass its `wheel` path and `wheel_sha256` together.

| Operation | Input from AgentLab | Output |
| --- | --- | --- |
| `group` | Public dialogue evidence, model and endpoint | Groups and their member IDs |
| `reflect` | Selected problem, confirmed examples, public evidence IDs, readable paths and pinned text snapshot | Hypotheses with evidence IDs and suggested fixes, or insufficient evidence |
| `prepare_candidates` | Selected hypotheses, pinned parent snapshot, writable paths and pinned manifest | Candidate snapshot, content and dependency digests, and patch, or editor decline |
| `compare` | Pinned manifest and corpus hashes, snapshot hashes, focus cases, paired schedule and measurements | Decision, thresholds and measurement IDs |

Use a fresh private workspace for each invocation. For `reflect` and `prepare_candidates`, set `parent` to the SHA-256 of the JSON map from relative UTF-8 text paths to their SHA-256 digests. Serialize the map with Python's default JSON separators, `sort_keys=True` and `ensure_ascii=False`. Pass the snapshot in `root/parent` for `reflect` and under the manifest's `seed_root/texts` for `prepare_candidates`. The Reflector's `paths` must name every file in its snapshot. The Editor gets one campaign attempt and reads the manifest's readable paths and the selected writable paths. A selected directory ends in `/`.

The `editor_evidence_contract` capability advertises `replay-records/1`. To attach public replays to `prepare_candidates`, pass `editor_evidence` with these maps.

- `references` maps each distinct evidence ID cited by the selected hypotheses to a lowercase SHA-256 record ID. AgentLab uses the pinned measurement ID for a replay and a digest of the public dialogue record for a recording.
- `records` maps exactly those record IDs to records containing the public `case_id` and an ordered, nonempty `turns` list. Each turn contains only the strings `customer` and `assistant`. For recorded conversations an empty side preserves consecutive messages by the same speaker or a conversation that starts with the agent.

Use the original, short ASCII evidence IDs from the hypotheses. The Editor can read a replay by a cited ID, and all cited IDs bound to the same measurement resolve to one catalog record. The adapter validates this closed record shape before invoking the Editor. A successful response to a request that carries `editor_evidence` includes `editor_evidence_contract: "replay-records/1"`. When passing the contract in a request, supply the evidence maps as well. Existing callers can omit both fields.

For `compare`, each row carries `case_id`, `repeat`, `side`, `slot`, `snapshot`, `measurement_id`, `score` and `critical`. Use integers for `repeat` and `slot`. The score is in [0, 1]. An unresolved score or critical verdict is null. A confirmed critical violation on a candidate vetoes it, including when other measurements are missing. Missing measurements otherwise produce `comparison_unavailable`. The `pinned-corpus/1` protocol uses the point gates, reported provenance and negligible execution noise of manifest `/16`. AgentLab performs its held-out confirmation separately.

The optional `editor_evidence_reader` capability advertises `read_evidence/1`. To inspect a replay offline, call `read_editor_evidence` with `editor_evidence`, selected `hypotheses` and a cited `evidence_id`. It uses the Editor's catalog reader and returns the public replay record and `editor_evidence_contract`. Unknown or unselected IDs fail.
