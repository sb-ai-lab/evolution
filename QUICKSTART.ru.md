# Ваша первая кампания Evolution

[English](QUICKSTART.md) · [Русский](QUICKSTART.ru.md)

Это руководство проведёт вас от публичного репозитория до завершённой кампании и выбранных ею файлов. Пример использует детерминированного эталонного агента и роли по заданному сценарию: ему не нужны API-ключ, вызовы модели, внешний агент или скачанный набор данных. Он проверяет, что процесс кампании работает, но не измеряет качество работы реального агента.

Команды ниже используют Bash или Zsh и Python 3.11.3 или новее. Нужны два терминала: один для Target Service и один для кампании. Запускайте оба из одного каталога и активируйте одно и то же окружение Python. Справочные руководства по ссылкам доступны на английском языке.

## 1. Установите бета-версию

Клонируйте публичный репозиторий, затем установите бета-версию из этой рабочей копии:

```bash
git clone https://github.com/sb-ai-lab/evolution.git
cd evolution
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[tree]"
evo --version
```

Для описанной в документации рабочей копии бета-версии последняя команда должна вывести `evo 2.0.0b18`. Дополнительный набор `[tree]` устанавливает зависимости для кампаний tree. При установке могут скачиваться зависимости. Если версия отличается, прежде чем продолжать, воспользуйтесь документацией для полученной вами версии.

Если команда предоставила вам wheel-файл, создайте и активируйте новое окружение, затем установите именно этот файл:

```bash
python -m pip install "/absolute/path/to/evo_skills-2.0.0b18-py3-none-any.whl[tree]"
evo --version
```

Замените путь на путь к полученному файлу. Не считайте, что эта бета-версия опубликована в PyPI. При установке из wheel-файла выполняйте следующие шаги в пустом рабочем каталоге.

## 2. Создайте пример

```bash
evo-target init ./demo
```

Будут созданы:

```text
demo/
├── manifest.json         # all campaign settings
├── seed/
│   ├── skills/SKILL.md   # the starting instructions
│   └── uv.lock           # a dependency file included in the tree identity
├── corpus.jsonl          # two evaluation cases
├── scorer/score.py       # gives each answer a score and verdict
├── reflector/reflect.py # points the editor at the failing behavior
└── editor/edit.py        # writes the example improvement
```

`manifest.json` — документ формата `evolution-v2-manifest/15`, текущего формата манифеста, с рекомендованными настройками. Они описаны в [справочнике манифеста](docs/manifest-v2.md#stable-family-keys-manifest-15).

`init` отказывается работать с непустым каталогом назначения. Если `demo` уже существует, выберите другое имя и используйте его в следующих командах. Не удаляйте существующий запуск только ради повторения учебного примера.

## 3. Запустите Target Service

В терминале 1:

```bash
evo-target serve ./demo/manifest.json
```

Дождитесь строки JSON с `"status": "listening"`. Оставьте этот терминал работающим. Адрес по умолчанию — `http://127.0.0.1:8765`.

Этот сервис — агент примера. На каждое сообщение он отвечает первой строкой загруженного `skills/SKILL.md`, за которой следует сообщение. В реальной интеграции вместо него ваш бэкенд запускает агента.

## 4. Проверьте соединение и запустите кампанию

В терминале 2 активируйте то же окружение и вернитесь в тот же рабочий каталог:

```bash
source .venv/bin/activate
evo tree conformance --manifest ./demo/manifest.json
```

Проверка соответствия проверяет, соблюдает ли сервис протокол target, в том числе загрузку запрошенных файлов и правильную работу с сессиями. Её JSON-отчёт должен содержать `"ok": true` и пустой список `leaked`.

Теперь запустите кампанию:

```bash
evo tree evolve --manifest ./demo/manifest.json --run-dir ./demo/run-1 \
  > ./demo/result.json
```

Кампания выводит один JSON с результатом в stdout; здесь он сохраняется как `demo/result.json`. Ход выполнения и инструкции по продолжению выводятся в stderr. Этот файл с результатом создаёт оболочка; собственные записи кампании Evolution хранит в `demo/run-1`.

## 5. Прочитайте результат

```bash
python - <<'PY'
import json
from pathlib import Path

result = json.loads(Path("demo/result.json").read_text())
print("State:", result["terminal"])
print("Outcome:", result["finished"])
print("Champion:", result["status"]["final_champion"])
print("Files:", result["status"]["campaign_outcome"]["champion_path"])
PY
```

Для неизменённого примера ожидается следующее:

- `terminal` имеет значение `finished`, исход — `completed`, причина — `rounds_exhausted`.
- Итоговый Champion — `v1`, он сохранён в `demo/run-1/artifacts/champions/v1`.
- В первом раунде выбирается отредактированная версия. Во втором не находится оставшихся провальных кейсов, и он штатно завершается.

Сравните файлы:

```bash
cat ./demo/seed/skills/SKILL.md
cat ./demo/run-1/artifacts/champions/v1/skills/SKILL.md
```

Выбранная копия начинается с `IMPROVED`; исходные файлы не меняются. Оценщик примера вознаграждает этот маркер, поэтому результат проверяет передачу файлов и выбор версии, а не качество реального агента.

После успешного завершения может появиться сообщение `continue:`. Оно объясняет, как начать следующую кампанию; это не ошибка, и для завершения примера ничего делать не нужно.

## 6. Остановите или повторите пример

Когда закончите, нажмите Ctrl+C в терминале 1, чтобы остановить сервис. Чтобы провести отдельный эксперимент с тем же примером, снова запустите сервис и используйте новый каталог, например `./demo/run-2`.

Повторное использование `./demo/run-1` читает существующую кампанию. Оно не удаляет запуск и не добавляет раунды в уже завершённую кампанию. Для более длительного эксперимента, продолжающего работу с её Champion, следуйте разделу [о продолжении завершённой кампании](docs/running-campaigns.md#continue-a-completed-campaign).

## Если что-то пошло не так

Если запуск остановился и вы не знаете почему, начните с раздела [«Запуск завершился с ошибкой: начните здесь»](docs/running-campaigns.md#a-run-failed-start-here): там приведены команда проверки состояния, расположение журналов и сведения, которые стоит приложить к запросу о помощи.

| Что вы видите | Что делать |
|---|---|
| `evo` или `evo-target` не найдены | Активируйте окружение, в котором установлен пакет. |
| `cannot bind` | Возможно, порт 8765 занят. Измените `target.base_url` в `demo/manifest.json` до первого запуска, затем перезапустите сервис. |
| Отказ в соединении или неудачная проверка работоспособности | Убедитесь, что терминал 1 всё ещё работает и использует тот же манифест. |
| `scorer_invalid at scorer.argv` | Пример запускает `python3`. Убедитесь, что он доступен в `PATH` активированного окружения. |
| `refused: ...` | Найдите в stderr неверную настройку или изменённые входные данные. См. [отказы](docs/running-campaigns.md#handle-a-refusal). |
| `suspended: ...` | Устраните указанную причину, затем повторите ту же команду `evolve`. См. [восстановление после ошибки](docs/running-campaigns.md#resume-after-a-failure). |
